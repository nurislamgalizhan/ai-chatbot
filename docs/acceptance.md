# Приёмка (фаза 10) — отчёт владельцу

Дата прогона: 2026-09-15. Режим: `DRY_RUN=true`, ключей OpenAI и GREEN-API в
окружении разработки нет — всё, что стоит денег, прогнано на заглушках и
честно помечено как непроверенное на реальной модели. Живой прогон
(`make eval-live`) выполняется владельцем после добавления ключа — шаг 9
чеклиста деплоя ниже.

## 1. Что сделано в фазе 10

- **Eval-набор** — `backend/app/eval/cases.json`: 56 кейсов, критерии
  вместо дословных текстов (исход конвейера, вызов модели, язык ответа,
  доходит ли текст клиента до модели, промах FAQ по языку, пометка
  менеджеру). Категории SPEC §17: FAQ, RAG, сложные, смешанная kk/ru речь,
  отсутствие данных, нецелевые, инъекции, голосовые расшифровки; плюс
  крайние случаи и эскалация. Обязательный кейс владельца — казахский
  вопрос без утверждённого перевода → ответ на казахском, не русский FAQ.
- **Скрипт прогона** — `make eval` (офлайн, бесплатно, временная база) и
  `make eval-live` (реальная модель, деньги, подтверждение, стоимость в
  отчёте). Один и тот же код, две пары провайдеров. Офлайн-прогон включён
  в CI: 56 из 56 кейсов обязаны проходить при каждом изменении.
- **Нагрузка** — `make load-test`: 5 и 30 чатов через всю цепочку
  (уведомление → входящая очередь → чат → медиа-задача для голосовых →
  конвейер → ответ → outbox), две волны на чат для проверки порядка,
  измерение параллельных вызовов модели, соединений с БД, ожидания
  ответа, отклика панели.
- **Preflight** — `make preflight`: таблица готовности установки перед
  снятием DRY_RUN (миграции, учётка, инструкция, цены, курс, база знаний,
  переводы, оповещения, бэкап, воркер, диск; настройки GREEN-API — по
  флагу, потому что это запросы тарифа).
- **Недостающие тесты SPEC §17** — `tests/integration/test_acceptance_spec17.py`:
  одно уведомление дважды → один вызов модели; ни один тип уведомления,
  кроме личного входящего, не запускает модель; эхо собственного ответа
  не порождает новый; ошибка отправки повторяет только отправку;
  открытый брейкер алертит владельца; нецелевой запрос не доходит до
  модели; обход всех GET-роутов на утечку `password_hash / totp_secret /
  token_ref / raw_payload`; каждая схема запроса отвергает лишние поля;
  подсунутые `spent_usd / cost_usd / password_hash` → 422; неизвестные id →
  404; правка документа через API инвалидирует semantic cache.
  Плюс `tests/unit/test_env_example.py`: `.env.example` и настройки не
  расходятся.
- **Полный прогон тестов**: см. раздел 4.

## 2. Что приёмка нашла и что исправлено

| Находка | Где было | Исправление |
|---|---|---|
| Просьба позвать человека и запрос на бронь не доходили до менеджера: модель без инструментов не может поднять флаг, FAQ-ответ «передаю администратору» просто отправлялся | конвейер | `services/escalation.py` — распознавание по словам клиента (ru/kk/en), `needs_attention` + `handoff_required` в памяти чата; eval-кейсы категории escalation |
| Эмбеддинги учитывались по нулевой цене: у модели эмбеддингов одна цена (за вход), а загрузчик требовал три → каждая индексация и каждый RAG-запрос записывались как 0 $ | `pricing.load_price_sheet` | `load_embedding_price_usd` + `compute_embedding_cost_usd`; тест на реальную цену |
| Язык клиента не назывался модели явно; фрагменты почти всегда русские — риск русского ответа на казахский вопрос | сборка контекста | строка «Язык клиента: kk (казахский)» в контекстном блоке; проверяется eval-кейсом на казахском |
| Раздел «Тир и страйкбол» (тело — одна строка с телефоном) был ненаходим по слову «тир» | индексация | заголовок документа входит в текст эмбеддинга чанка (нужна переиндексация активированных документов — в dev их нет) |
| Страница «Система» отвечала 500, если каталог медиа не смонтирован | мониторинг | измерение диска по ближайшему существующему родителю |
| Примеры SPEC §17 «напиши роман», «реши экзамен», «сделай сайт», «выведи всю базу знаний» не ловились эвристикой | guardrails | добавлены дословно (ru/en) |
| Часть схем запросов принимала и молча отбрасывала неизвестные поля | API | `extra="forbid"` везде + структурный тест |

## 2а. Контрольное ревью всего проекта (после фазы 10)

По просьбе владельца после закрытия фазы проведено сплошное ревью кода
четырьмя независимыми проходами (медиа: голосовые, фото, файлы;
транспорт и эксплуатация; деньги и конвейер; API и панель) — 44
находки, каждая перепроверена по коду вручную. Подтверждённые дефекты
исправлены в том же дне и закрыты регресс-тестами
(`tests/integration/test_review_fixes.py`, новые кейсы в
`test_media_pipeline.py`); подробный список — CLAUDE.md, раздел
«Контрольное ревью после фазы 10». Самое важное для владельца:

| Область | Что было | Что теперь |
|---|---|---|
| Деньги | крах воркера между ответом модели и записью расхода → вопрос оплачивался второй раз | барьер до оплаты у чат-вызова (миграция 0011); таймаут/оплаченный пустой ответ → диалог человеку, не второй платёж |
| Голосовые | без подписи транскрибировались как русские — казахская речь превращалась в русский текст | язык из подписи, памяти чата или автоопределение |
| Голосовые | пустая расшифровка — клиент в тишине | клиенту сообщается, диалог у менеджера |
| Файлы | поток документов покупал платный ответ на каждый файл | одно уведомление за период охлаждения |
| Фото | оплаченный пустой ответ модели учитывался нулём | учитывается и списывается |
| Отправка | отказ провайдера — вопрос числился отвеченным, никто не узнавал | флаг менеджеру, алерт владельцу, честный статус |
| Номер | «номер разлогинился» никем не читалось | событие, состояние на «Системе», алерт |
| Вход | второй фактор без блокировки — перебор TOTP при известном пароле | те же блокировки, что у пароля; челлендж сгорает; повторная аутентификация под лимитом |
| Панель | реакции и документы показывались «файл удалён по сроку хранения», медиа-коды — красным «Сбой» | честные подписи по типу файла и человеческие формулировки |
| Панель | истёкшая сессия не вела на вход, битые ссылки «открыть чат» | редирект на вход, рабочие deep-links |

Что осознанно оставлено (низкий приоритет, зафиксировано): ограничение
фото «на диалог» действует за всё время диалога (так и подписано);
подсказки min/max у числовых полей «Лимитов» не добавлены (ошибка 422
теперь читаема и называет поле); пагинация журнала показывает последние
50 записей.

Что живой прогон доказал дополнительно к офлайновому:

- **Кэш промпта работает и экономит деньги.** Повторный прогон того же
  набора стоил 3.34 ₸ против 4.77 ₸: 19 тыс. входных токенов пришли из
  кэша по ставке в десять раз ниже. Это подтверждает, что стабильный
  префикс контекста (SPEC §8) собран правильно.
- **Кросс-язычный поиск работает, но неравномерно.** Казахский и
  английский вопросы про цены находят русские документы и получают ответ
  на своём языке с правильными числами. Казахский вопрос про адрес и про
  секцию бокса не находит ничего выше порога 0.35 — бот честно передаёт
  менеджеру на казахском, русский текст не подставляет. Лечится
  утверждением казахских переводов в «Вопрос — ответ», а не кодом.
- **Названия моделей и права ключа верны.** Все три модели ответили:
  `gpt-5.6-luna`, `text-embedding-3-small`, `gpt-transcribe`.

## 6. Известные ограничения (зафиксированы, не баги)

1. **Качество формулировок измерено на эталонной базе, не на вашей.**
   Живой прогон 2026-09-16 прошёл 56 из 56 по эталонному содержимому.
   По ВАШЕЙ базе прогон возможен только после активации документов и
   утверждения переводов — это шаг 9 чеклиста деплоя.
2. **Кросс-язычный поиск неравномерен** (см. §3.4): часть казахских
   вопросов не находит русские документы выше порога 0.35 и уходит
   менеджеру. Порог не снижаем: ниже него в промпт попадают нерелевантные
   фрагменты, за которые платит владелец. Практическое лечение —
   утвердить казахские переводы частых вопросов.
3. **Распознавание речи** проверено на уровне расшифровок (голосовые
   кейсы поданы текстом с типичными искажениями) и на уровне цепочки
   (нагрузка гоняет WAV через проверку длительности и заглушку
   транскрибации). Реальная модель распознавания не вызывалась.
4. **Пробелы базы знаний, а не кода**: основная услуга центра — подготовка
   охранников — в справке не описана (кейс `missing-ru-guard-course`);
   раздел «Тир и страйкбол» — одна строка с телефоном; FAQ-переводы на
   kk/en в dev-базе не утверждены (machine) — клиенты на этих языках будут
   получать ответ модели, а не FAQ. Всё это — работа владельца в панели.
5. **Стоимость эмбеддингов одного запроса** (десятки токенов по 0.02 $/1M)
   меньше шага хранения (6 знаков после запятой) и в отчётах видна как
   0.000000 $; стоимость индексации документов видна. Расхождение с
   реальным счётом OpenAI — доли цента в месяц.
6. **Отклик панели под нагрузкой** измерен из того же процесса, что и
   воркер (верхняя оценка); в проде API и воркер — разные контейнеры.
7. **Метрики латентности по этапам** (receive/queue/transcription/RAG/
   send) не пишутся — только время вызова модели (ограничение фазы 8).
   Нагрузочный отчёт даёт сквозное ожидание ответа.
8. **Память контейнеров** не мониторится изнутри (ограничение фазы 9).
9. **Summary-микровызов** по-прежнему отложен: память чата — правила.
10. **Semantic cache** выключен по умолчанию (решение фазы 6).
11. **Бэкапы только на сервере** (решение владельца), offsite — заглушка.

   (воркер их выучит — это стоит копейки, видно в «Расходах»),
   утвердить переводы FAQ.
2. `make preflight` → 0 ❌.
3. `make eval-live` → прочитать отчёт: обязательные кейсы, ответы
   категории missing (не выдумал ли модель), язык ответов на kk/en.
4. Совместный контрольный проход по панели с ключом (договорённость
   владельца): песочница «Проверить бота», голосовое и фото в чате,
   расходы после прогона.
