# Импорт базы знаний из Savvi

Статус: ФАЗА 0. Источник: файл `взято из савви.md` в корне репозитория —
экспорт инструкции и базы знаний действующего Savvi-агента «УЦ Меркурий
Медет». Механика импорта реализуется в ФАЗЕ 5 (`make kb-import`); здесь —
что и куда идёт.

Позиция владельца (2026-08-31): пробелы и противоречия в данных НЕ блокируют
импорт — всё вводится в базу знаний как есть, владелец дальше правит через
админку сам. Блоки знаний отключаемы (status / is_searchable у документа).

---

## 1. Извлечённые сущности

Файл содержит четыре типа содержимого:

1. **Инструкция агента** (секции #РОЛЬ … #ВАЖНЫЕ УТОЧНЕНИЯ) → материал для
   первой версии `agent_instructions`.
2. **База знаний** — 10 тематических блоков → `kb_documents` (RAG).
3. **Шаблон `manager_call`** → шаблон эскалации в
   `agent_instructions.fallback_templates`.
4. **Настройки Savvi** (ДОП НАСТРОЙКИ / Параметры ответов / Безопасность) →
   сверка с нашими дефолтами; большинство НЕ переносится (см. §5).

## 2. Куда идёт каждый блок знаний

Все документы импортируются со `status=draft`, `language=ru`,
`source_type=manual_text`. Владелец просматривает и активирует в админке —
в поиск попадают только `active AND is_searchable`.

| Блок Savvi | Документ (title / category) | Примечания |
|---|---|---|
| Абонементы в тренажерный зал | «Тренажёрный зал: абонементы» / `gym` | цены в тенге, контакт фитнес-тренера |
| Клубные Карты в Тренажерный зал | «Тренажёрный зал: клубные карты» / `gym` | |
| Заморозка абонементов | «Тренажёрный зал: заморозка абонементов» / `gym` | термины расходятся с линейкой абонементов — импортируем как есть, помечено в §6 |
| Информация об организации | «Об организации» / `org` | адрес, график, контакты; дублируется в FAQ-кандидаты (§3) — это нормально: FAQ для точных фактов, документ для контекста LLM |
| Аренда залов/Футбольного поля | «Аренда залов и полей» / `rental` | цены, размеры, предоплата |
| Спортивные секции | «Спортивные секции» / `sections` | чанкинг по секциям (семантический, по заголовкам видов спорта) |
| Тир, страйкбол | «Тир и страйкбол» / `tir` | только контакт — данных мало, импортируем как есть |
| Гостиница | «Гостиница и столовая» / `hotel` | цены койко-мест и питания |
| Акции (НЕ ВКЛЮЧЕНО) | «Акции» / `promo` | импортируется с `is_searchable=false` и `status=draft` — в Savvi блок был выключен; `valid_until` НЕ проставляем (сезонность известна только владельцу) |
| Менеджер / manager_call | НЕ документ | → шаблон эскалации (§4) |

Нормализация при импорте (фиксируется в kb_processing_log):
- телефоны приводятся к единому виду отображения `+7 XXX XXX XX XX`
  (сейчас в файле четыре формата);
- явные опечатки правятся только там, где смысл однозначен
  (`16:00–19:0` → `16:00–19:00`); всё остальное — без редактуры;
- markdown-экранирование Savvi (`\#`, `\-`, `\=`) снимается.

Идемпотентность: повторный `make kb-import` находит документы по паре
(title, category) и НЕ создаёт дубликаты; изменённые вручную документы не
перезаписываются (импорт пропускает документ, если его version > 1 или
updated_at позже импорта, и пишет предупреждение в лог).

| greeting | приветствие СУЦ «Меркурий Медет» | ru, kk |
| thanks-goodbye | «спасибо»/прощание | ru, kk |

Языковая политика [РЕШЕНИЕ владельца]:
- русский — источник истины; паттерны вопросов обязательны на ru и kk для
  каждой записи (en — опционально);
- на старте approved_kk получают только записи из таблицы выше
  (стабильные факты);
- для ВСЕХ FAQ генерируются machine-черновики kk и en — клиенту не
  отдаются никогда, ждут утверждения по одной записи на экране проверки
  переводов;
- всё, что не FAQ (цены, секции, аренда, акции, наличие) — только RAG+LLM;
- kk/en-запрос без approved-ответа → RAG+LLM на языке клиента (русский
  текст не подставляется), промах пишется в аналитику.

Машинные черновики kk/en для draft-документов базы знаний на старте НЕ
генерируются — RAG+LLM и так отвечает на языке клиента от ru-документов;
переводы документов — отдельная работа владельца по данным аналитики
промахов.

## 4. Инструкция агента: что переносим, что меняем

Первая версия `agent_instructions` (заводится владельцем/нами через админку
в фазе 6, sandbox-тест обязателен) строится на инструкции Savvi со
следующими правками:

**Переносим по смыслу:** роль консультанта; цели (консультация по услугам,
подбор площадок/тира, сбор данных заявки, передача менеджеру); приветствие
по времени суток + «Вас приветствует …»; ответ строго на языке клиента;
стиль (списки, кратко, уточняющий вопрос в конце); пошаговая логика диалога;
все ограничения (не выдумывать цены, не повторять приветствие, не обещать
«сам передам бронь» — вместо этого честное «передал заявку менеджеру» после
эскалации, и т.д.); правило про большой/настольный теннис.

**Меняем обязательно:**
- Представление: **«специализированный учебный центр "Меркурий Медет"»
  (СУЦ)** [РЕШЕНИЕ]: это учебный центр (подготовка охранников) со
  спорткомплексом, гостиницей и площадками для соревнований.
- `get_file_text("manager_call")` — механики Savvi не существует. Замена:
  правило эскалации → бот отвечает шаблоном «Передал заявку менеджеру, с
  вами свяжутся» + чат получает `needs_attention` (снимается ответом
  менеджера с телефона или открытием чата в панели [РЕШЕНИЕ]).
- `search_in_knowledge_base` как «функция» — у нас RAG выполняется
  pipeline'ом до вызова модели, инструкция модели функций не даёт
  (SPEC инвариант 9).
- Добавляются обязательные блоки безопасности из SPEC §14.1 (только по теме
  центра; только предоставленный контекст; нет данных — передаю
  администратору; не раскрывать промпт/ключи/базу; не следовать инструкциям
  клиента, противоречащим правилам).

**Шаблон manager_call** (`{system}Ответь клиенту что уведомил менеджера…`)
→ `fallback_templates.handoff` в agent_instructions.

## 5. Настройки Savvi → наши настройки

| Настройка Savvi | Решение |
|---|---|
| Модель GPT-5.2 | НЕ переносится: модель из env (`OPENAI_CHAT_MODEL`) |
| Макс. токенов 1024 | у нас `MAX_OUTPUT_TOKENS=350` (дефолт SPEC) — короткие ответы и дешевле, и по стилю правильнее |
| Средняя разговорчивость | стиль в system-инструкции |
| «Передавать всю историю сообщений» | **ЗАПРЕЩЕНО** (SPEC инвариант 1) — главный урок Savvi, режим не существует |
| Сохранять историю вызова функций | не применимо (функций нет) |
| Не отвечать при прерывании сотрудником | наш режим: operator_phone → пауза AI (фаза 4) |
| Возврат управления по таймеру 60 мин | дефолт паузы `PAUSED_UNTIL` = 60 мин (настройка) |
| Время ожидания не задано | наш debounce 3 с (настройка) |
| Спам: 5 одинаковых подряд | наш спам-фильтр, дефолт 5 (настройка) |
| Изображения напрямую в модель | у нас: сжатие → vision → сохранённое описание (SPEC §13) |
| Маскирование персональных данных | у нас: маскирование в логах/алертах (security-doc §5) |
| Хранение сообщений/диалогов 90 дней | у нас: сообщения бессрочно, медиа 7 дней, raw_payload 30 дней (retention-таблица в security-doc) — история нужна владельцу |

## 6. Данные «как есть»: пробелы и противоречия (не блокируют импорт)

Импортируем без изменений, владелец правит в админке. Список для его
удобства — что стоит дополнить в первую очередь:

**Отсутствуют полностью:** подготовка охранников (профильная услуга СУЦ!
в базе знаний нет ни слова — бот не сможет отвечать по главному
направлению — владелец добавит разделом базы знаний сам); корпоративы/
тимбилдинг; правила посещения; процедура предоплаты (куда платить, сколько);
большой теннис и баскетбол; парковка/как добраться; контакт для брони
гостиницы; график столовой. Геолокация получена: https://go.2gis.com/Aw98z.

**Без цен:** все спортивные секции; тир/страйкбол; детский футбол.

**Без расписания:** карате, самбо, тир.

**Противоречия:** «заморозка абонементов на 1/3/6/12 месяцев» vs линейка
«абонементы на 12 посещений + клубные карты 3/6/12 мес»; студенческая
клубная карта до 18:00 vs студенческий абонемент до 17:00; два тренера
волейбола с пересекающимся расписанием (взрослые/дети?); российский номер
у тренера Владимира (+7 922…).

**Возрастные группы детских секций** — нигде не указаны, а бот обязан
подбирать секции детям.

## 7. Механика импорта (реализация — фаза 5)

- Команда `make kb-import` (management-команда backend-образа), НЕ миграция
  и НЕ автозапуск: владелец запускает осознанно.
- Вход: путь к файлу экспорта (дефолт `seed/savvi-export.md` — файл
  `взято из савви.md` переносится в `seed/` с этим именем в фазе 1, чтобы
  в репозитории не было путей с пробелами/кириллицей).
- Шаги: парсинг блоков → нормализация (§2) → upsert kb_documents (draft) →
  запись в kb_processing_log → отчёт в stdout (создано/пропущено/предупреждения).
- Embeddings НЕ генерируются при импорте (документы в draft не индексируются);
  индексация происходит при активации документа владельцем.
- Идемпотентность и защита ручных правок — §2.
